# بُرهان · BURHAN

**Regulatory Evidence Twin — التوأم الرقابي الحي للمنشآت النووية**

نموذج أولي تفاعلي (Controlled Prototype) يعرض فكرة بُرهان: ربط المتطلب الرقابي
بالواقع الفعلي للمنشأة وبالدليل الذي يثبته، داخل شبكة واحدة يمكن تتبعها.

> جميع المنشآت والأنظمة والمكونات والسجلات المعروضة **افتراضية** ولا تمثل منشأة حقيقية.
> مؤشر «تكامل الأدلة» هو مؤشر تجريبي لترتيب الأولويات داخل النموذج الأولي فقط،
> وليس تقييمًا رسميًا لسلامة نووية.

---

## ما الذي يعرضه النموذج؟

عرض من ١٤ شريحة، مبني بـ React، يغطي:

| # | الشريحة | المحتوى |
|---|---------|---------|
| 01 | الافتتاحية | الخطر النووي لا يبدأ دائمًا بحادث |
| 02 | المشكلة | التغييرات التسعة التي يراقبها بُرهان |
| 03 | المبدأ | مثلث `Configuration Integrity` — تفاعلي: محاكاة انحراف التهيئة |
| 04 | شبكة الأدلة | من المتطلب الرقابي إلى الدليل |
| 05 | المحاكاة | أربعة أحداث على `Cooling System CS-01` — تفاعلي |
| 06 | التفسير | Explainable AI و Human-in-the-Loop |
| 07 | البنية | الطبقات السبع، من البيانات إلى القرار البشري |
| 08 | التطبيقات | Command Center · Regulatory Workspace · Inspector |
| 09 | سير الحالة | دورة حياة الحالة الرقابية و Audit Trail |
| 10 | الحوكمة | RBAC والفصل بين الجهة الرقابية والمشغل |
| 11 | الذكاء الرقابي | الأنماط، الذاكرة المؤسسية، البحث داخل الأدلة |
| 12 | النطاق والمراحل | نطاق النموذج الأولي والمراحل الست |
| 13 | الأثر | ما الذي يتغير عمليًا |
| 14 | الخاتمة | الرؤية، وما لا يدّعيه المشروع |

### العناصر التفاعلية

- **شريحة 03** — زر يحوّل المثلث من `INTEGRITY` إلى `CONFIGURATION DEVIATION`.
- **شريحة 05** — تشغيل الأحداث الأربعة واحدًا تلو الآخر: مؤشر تكامل الأدلة ينتقل
  `96 → 86 → 72 → 60`، وشريط الحالة وعقد شبكة الأدلة تتغيّر معه، ثم تظهر بطاقة
  `REGULATORY ATTENTION`.

### التنقل

- `←` أو `Space` للشريحة التالية، `→` للسابقة، `Home` / `End` للأولى والأخيرة.
- زر الفهرس في أعلى الشاشة، أو الانتقال المباشر عبر الرابط: `index.html#demo`.

## التشغيل والبناء

```bash
npm install
npm run dev      # خادم التطوير
npm run build    # يبني الموقع الثابت في جذر المستودع
npm run preview  # معاينة الناتج المبني
```

### بنية المشروع

```text
src/                 المصدر (جذر Vite)
├── index.html       نقطة الدخول أثناء التطوير
├── main.jsx
├── App.jsx          هيكل العرض والتنقل بين الشرائح
├── slides.jsx       الشرائح الأربع عشرة
├── components.jsx   المكونات البصرية (الخلفية، المثلث، الشبكة، المؤشر، التنبيه)
├── data.js          بيانات العرض الافتراضية
└── styles.css       نظام التصميم والأنماط

index.html           ناتج البناء — الصفحة المنشورة
assets/              ناتج البناء (JS + CSS)
```

`npm run build` يكتب ناتجه في **جذر المستودع** حتى تبقى `index.html` قابلة للنشر
مباشرة كموقع ثابت (GitHub Pages مثلًا). `emptyOutDir` معطّل حتى لا يمس البناء
مجلد المصدر، ولذلك يمسح `prebuild` مجلد `assets/` قبل كل بناء.
ناتج البناء مرفوع مع المصدر عمدًا لهذا السبب.

> ينبّه Vite أثناء البناء إلى أن `outDir` مجلد أعلى من `root`. هذا مقصود هنا،
> وتعطيل `emptyOutDir` يمنع أي مساس بملفات المصدر.

## الهوية البصرية

الخلفية `#05070F` مع الأزرق النووي `#00E5FF`، وحالات `safe / warning / critical`،
وخط `IBM Plex Sans Arabic` للنصوص و `IBM Plex Mono` للرموز الرقابية.
الأسلوب مستوحى من غرف التحكم والأجهزة العلمية والمخططات الهندسية.
