# معيار

> راجع نصك وافهم المراجع النظامية المرتبطة به قبل النشر

معيار موقع ثابت (HTML وJavaScript فقط) له وظيفتان:

1. **فحص نص** قبل نشره، وتحديد مواضع الإشكال المحتملة وفق المراجع المتاحة، مع ذكر السبب واقتراح صياغة بديلة.
2. **«اسأل معيار»**: الإجابة عن سؤال يخص النشر والمحتوى الإعلامي، مع ذكر المادة والمصدر.

نطاق التقييم هو **ستة مراجع فقط** مرفقة ومعالجة في هذا المستودع، وليس جميع الأنظمة السعودية. ما يعرضه معيار تقييم مساعد، وليس حكمًا قانونيًا نهائيًا. التحقق من الحسابات وموثوقيتها مؤجل لمرحلة لاحقة.

---

## 1. طريقة العمل

```
نص المستخدم ─► بحث محلي داخل المتصفح (BM25 عربي) ─► مقاطع ذات صلة فقط
                                                     │
                                                     ▼
        اختيار النموذج تلقائيًا ─► طلب تحليل واحد من المتصفح مباشرة إلى المزود (بمفتاح المستخدم)
        ─► نتيجة JSON منظمة ─► فحص البنية والاستشهادات ─► عرض
```

- الفحص يتطلب مفتاح API من المزود (OpenAI أو Anthropic). لا يوجد مسار بدون مفتاح.
- لا يختار المستخدم النموذج؛ يختاره معيار تلقائيًا (التفاصيل في القسم 7).

- **لا خادم ولا Proxy**، ولا تسجيل دخول، ولا قاعدة بيانات للمستخدمين، ولا دفع، ولا أدوات تتبع.
- المستخدم يدخل مفتاحه الخاص، ويتحمل تكلفة طلباته لدى المزود.
- لا يُرسل أي ملف PDF. يُرسل نص المستخدم مع المقاطع المختارة فقط (نحو 15 ألف حرف كحد أقصى تقريبًا).

## 2. التشغيل والنشر

المتطلبات للتطوير فقط: Node.js 18 أو أحدث. لإعادة بناء المراجع: Python 3 مع `pymupdf` و`fonttools`.

```bash
cd meyar
```

```bash
npm install
```

```bash
npm run dev
```

بناء النسخة الثابتة (تُكتب في `dist/`):

```bash
npm run build
```

معاينة البناء محليًا:

```bash
npm run preview
```

**النشر على Vercel:** من لوحة Vercel اختر Add New ← Project ← Import للمستودع، واضبط **Root Directory** على `meyar`، ثم Deploy. ملف `meyar/vercel.json` يحدد أوامر البناء ومجلد الإخراج وترويسات الأمان (CSP مع `frame-ancestors 'none'`، و`nosniff`، و`no-referrer`، و`X-Frame-Options: DENY`، و`Permissions-Policy`، و`HSTS`).

**النشر على استضافة أخرى:** ارفع محتويات `dist/` كما هي إلى أي استضافة ملفات ثابتة، مثل GitHub Pages أو Cloudflare Pages أو Netlify أو خادم ويب عادي. المسارات نسبية (`base: './'`)، فيعمل الموقع من أي مجلد فرعي. نسخة بناء جاهزة موجودة في `meyar/dist/`.

ملاحظة: سياسة CSP مضمّنة في `index.html` عبر وسم `meta`. إذا كانت الاستضافة تسمح بترويسات HTTP، فيُستحسن إضافة الترويسات التالية من جهة الاستضافة، لأن وسم `meta` لا يدعمها:
- `Content-Security-Policy` بالقيمة نفسها مع إضافة `frame-ancestors 'none'`.
- `X-Content-Type-Options: nosniff`.

## 3. تكاليف الاستضافة وحدودها

- الموقع ملفات ثابتة: صفحة وسكربت (نحو 60 ك.ب) وقاعدة مراجع (نحو 360 ك.ب، وتُضغط عند النقل). ملفات PDF الأصلية (نحو 30 م.ب) لا تُحمَّل إلا عند فتحها.
- كثير من مزودي الاستضافة الثابتة يقدمون خطة مجانية، **لكن لها حدود** في عرض النطاق وعدد الطلبات وحجم الموقع، وتُطبق شروط استخدام قد تتغير. عند تجاوز الحدود قد تلزم خطة مدفوعة، أو قد يُقيَّد الموقع. **لا يوجد وعد باستضافة مجانية غير محدودة.**
- تكلفة تحليل الذكاء الاصطناعي لا يتحملها صاحب الموقع: كل طلب يُرسل بمفتاح المستخدم ويُحتسب على حسابه لدى المزود.
- الموقع لا يعرض تكلفة نقدية للطلب، لأنه لا يملك بيانات تسعير حديثة موثقة. يعرض عدد التوكنز كما يعيده المزود.

## 4. المراجع: ما استُخدم وما استُبعد

جميع الملفات فُحصت من محتواها الفعلي، لا من أسمائها. البيانات الكاملة في `sources/documents.json`، وتظهر أيضًا في قسم «المراجع وحدود التغطية» داخل الموقع.

| المعرّف | الوثيقة | النوع | المواد | طريقة الاستخراج |
|---|---|---|---|---|
| `press-law` | نظام المطبوعات والنشر (م/32، 1421هـ) | نظام | 49 | طبقة نص رقمية فُكّت على مستوى الحروف |
| `press-law-exec-reg` | اللائحة التنفيذية لنظام المطبوعات والنشر (المعدلة 1439/11/9هـ) | لائحة | 99 | فك ترميز خط معيب بجدول حروف مُراجع بصريًا |
| `av-media-law` | نظام الإعلام المرئي والمسموع (م/33، 1439هـ) | نظام | 25 | ملف ممسوح ضوئيًا، نُسخ يدويًا وطوبق بصريًا |
| `av-media-exec-reg` | اللائحة التنفيذية لنظام الإعلام المرئي والمسموع | لائحة | 31 | فك ترميز خط بلا ترميز Unicode بجدول حروف مُراجع بصريًا |
| `gmedia-org` | تنظيم الهيئة العامة لتنظيم الإعلام (قرار 174، 1445هـ) | تنظيم واختصاصات جهة | المواد 1–3 | ملف ممسوح ضوئيًا، نُسخت الصفحات 1–5 |
| `age-rating` | التصنيف العمري (صفحة الهيئة العامة لتنظيم الإعلام) | دليل أو معيار رسمي تحتاج طبيعته تحديدًا | بلا ترقيم | طبقة نص رقمية |

**الأجزاء غير المعتمدة للاقتباس:**
- ملحقا اللائحة التنفيذية لنظام الإعلام المرئي والمسموع، (أ) دليل التراخيص و(ب) جدول المخالفات (صفحات PDF 26–56): جداول لم يُحفظ ترتيب أعمدتها عند الاستخراج. هي مخزنة ومعلَّمة بأنها غير معتمدة، ولا تُرسل إلى النموذج.
- تنظيم الهيئة العامة لتنظيم الإعلام، الصفحات 6–12 (مجلس الإدارة والشؤون المالية): لم تُنسخ، وهي خارج نطاق مراجعة المحتوى.
- نظام الإعلام المرئي والمسموع، الصفحة 2 (قرار مجلس الوزراء): لم تُنسخ.

**ملفات مستبعدة من الاستشهاد النظامي** (البصمات في `sources/documents.json`):
- تقرير حالة قطاع الإعلام في السعودية وفرص الاستثمار، الملخص التنفيذي 2024: تقرير قطاعي.
- تقرير حالة الطلب على المحتوى 2024: تقرير قطاعي.
- أربع محاضرات (إدارة التواصل والمنصات الإعلامية 1 و2، والوعي الإعلامي والمسؤولية الوطنية 1 و2): مواد تعليمية.

سبب الاستبعاد: لا يُستخدم تقرير سوقي أو محاضرة لإثبات مخالفة نظامية. هذه الملفات غير مضمّنة في المستودع.

### حالة التحقق من الحداثة

**لم تتحقق حداثة أي نسخة.** بيئة الإعداد لم تسمح بالوصول إلى `laws.boe.gov.sa` ولا `gmedia.gov.sa`، فلم يمكن مقارنة النسخ بالمصدر الرسمي، ولم يُسجَّل رابط رسمي لأي وثيقة (`official_url: null`). ملاحظات محددة:
- نظام المطبوعات والنشر: النص في الملف لا يُظهر أي تعديلات لاحقة. يلزم التحقق من وجود تعديلات، خاصة على مواد الضوابط والعقوبات (المادتان 9 و38).
- نظام الإعلام المرئي والمسموع ولائحته: يستخدمان أسماء جهات سابقة («وزارة الثقافة والإعلام»، «الهيئة العامة للإعلام المرئي والمسموع»). تنظيم 1445هـ المرفق أنشأ «الهيئة العامة لتنظيم الإعلام» محل تنظيم الهيئة السابق.
- اللائحة التنفيذية لنظام الإعلام المرئي والمسموع: لا تذكر تاريخ إصدار أو رقم قرار.

## 5. تجهيز المراجع وإعادة بنائها

```
sources/pdf/                 ملفات PDF الأصلية + SHA256SUMS
sources/text/*.txt           نسخ يدوي للملفات الممسوحة، مقسم بعلامات === PAGE n ===
sources/extracted/<id>/      نص مستخرج آليًا، ملف لكل صفحة PDF (لا يُحرر يدويًا)
sources/documents.json       بيانات الوثائق: النوع، الجهة، الإصدار، الحداثة، ملاحظات الاستخراج، المستبعدات
scripts/extract_all.sh       الخطوة 1: استخراج النص من ملفات PDF الرقمية
scripts/extract_royal.py     فك الترميز على مستوى الحروف (glyph) عبر جدول royal_map.py
scripts/extract_bukra.py     فك الترميز على مستوى الحروف عبر جدول bukra_map.py
scripts/normalize_letters.py توحيد ی/ھ/ک إلى ي/ه/ك
scripts/ocr.sh               OCR مساعد (Tesseract، العربية) لصنع مسودة النسخ اليدوي فقط
scripts/build_corpus.py      الخطوة 2: تقسيم المواد، والصفحات، والإحالات ← public/data/corpus.json
```

إعادة البناء الكاملة:

```bash
pip install pymupdf fonttools
```

```bash
npm run refs
```

إعادة تقسيم المواد فقط، بعد تعديل `sources/text` أو `documents.json`:

```bash
npm run corpus
```

**إضافة وثيقة أو تحديثها:**
1. ضع ملف PDF في `sources/pdf/` باسم ثابت بأحرف لاتينية صغيرة (مثل `new-law.pdf`).
2. إن كانت طبقة النص سليمة، أضف سطرًا في `extract_all.sh` يستخدم `extract_royal.py` (يعمل مع الخطوط ذات الترميز السليم). إن كان الملف ممسوحًا ضوئيًا، شغّل `scripts/ocr.sh` لصنع مسودة، ثم انسخ النص يدويًا إلى `sources/text/<id>.txt` بعد مطابقته بصريًا.
3. أضف بيانات الوثيقة في `sources/documents.json`: `segmenter` بقيمة `ordinal` للمواد المكتوبة بالكلمات، أو `numeric` للأرقام، أو `headings` للنصوص غير المرقمة. حدّث `reviewed_on` و`currency`، ولا تكتب `verified` إلا بعد مقارنة فعلية بالمصدر الرسمي.
4. شغّل `npm run refs` ثم `npm test`. اختبار سلامة المراجع يرفض أي تسلسل مواد غير متصل، وأي حرف بديل (U+FFFD)، وأي أخطاء معروفة في ترتيب «لا».

**ضمانات البيانات:**
- رقم المادة يُقبل فقط إذا طابق نمط الترقيم في الوثيقة وكان تاليًا للمادة السابقة مباشرة.
- لا يُخترع رقم مادة للنصوص غير المرقمة، فتُعرض باسم القسم.
- لكل مقطع: المعرّف، ورقم المادة، وصفحة PDF الفعلية، والصفحة المطبوعة إن اختلفت، والباب أو الفصل، والنص الأصلي، والإحالات المكتشفة (مثل «المادة الخامسة من النظام» تُربط بالنظام الأم).
- المادة الطويلة تُقسم عند حدود البنود المرقمة فقط. يُرفق مطلع المادة مع كل جزء، ويُشار إلى الجزء (1 من 2).
- النص المعروض اقتباسًا هو النص الأصلي. التطبيع، أي توحيد الهمزات وإزالة التشكيل، يُطبق على نسخة البحث فقط.

## 6. البحث المحلي

`src/search.ts`: بحث BM25 داخل المتصفح يعمل على مستويين، المقطع كاملًا وكل بند فيه.
- تطبيع عربي (الهمزات، التاء المربوطة، الألف المقصورة، التشكيل، التطويل) وتجذيع خفيف.
- قائمة مصطلحات متقاربة، مثل: إعلان/دعاية/ترويج، تبغ/سجائر، ترخيص/تصريح/فسح، خصوصية/صور.
- يُلحق بالنتائج المواد المحال إليها (مستوى واحد)، والتعريفات إذا ورد مصطلح معرَّف في المدخل.
- في «فحص نص» تُضمَّن دائمًا ضوابط المحتوى العامة: نظام الإعلام المرئي والمسموع م5، ولائحته م4، ونظام المطبوعات م9، ولائحته م73. هذا يقلل احتمال أن يفوت البحث اللفظي ضابطًا عامًا.
- إذا لم يعثر البحث على مقاطع مطابقة لسؤال، يعرض معيار «لا تكفي المراجع المتاحة للتقييم» محليًا **دون طلب مدفوع**، مع خيار صريح «أرسل رغم ذلك».
- يوضح الموقع أن البحث قد لا يسترجع كل مادة ذات صلة.

## 7. تكامل المزودين: ما اختُبر وما لم يُختبر

| المزود | الحالة |
|---|---|
| **Anthropic (Claude)** | **الاتصال المباشر من المتصفح اختُبر بطلب حقيقي** من Chromium إلى `https://api.anthropic.com/v1/messages` (`tests/cors-check.cjs`). دون الترويسة `anthropic-dangerous-direct-browser-access: true` يحجب المتصفح الطلب (CORS). مع الترويسة يصل خطأ المصادقة مقروءًا (401 `authentication_error`) عند استخدام مفتاح غير صالح عمدًا. **لم يُختبر تحليل كامل بمفتاح صالح**، لعدم وجود مفتاح، ولأنه لا يجوز استخدام مفتاح صاحب المشروع. |
| **OpenAI** | **جلب قائمة النماذج من المتصفح مباشرة نجح** من حساب المستخدم الفعلي، وظهر `gpt-5-chat-latest` ضمن نماذج حسابه، ما يثبت أن الاتصال المباشر من المتصفح مسموح لهذا الطلب. ووصل طلب التحليل (`POST /v1/responses`) من المتصفح إلى OpenAI وأعاد ردًّا مقروءًا (429 `insufficient_quota` لحساب بلا رصيد API)، فالاتصال المباشر يعمل. **لم تُختبر بعد نتيجة تحليل كاملة.** الكود يستخدم `text.format` من نوع `json_schema`. |

**روابط إنشاء المفاتيح:**
- `https://platform.claude.com/settings/keys`: تحقّق أنها صفحة قائمة (تطلب تسجيل الدخول).
- `https://platform.openai.com/api-keys`: **لم يمكن التحقق منها** من بيئة الإعداد بسبب حجب النطاق.

**اختيار النموذج تلقائي** (`resolveModel` في `src/providers.ts`). عند ضغط زر التنفيذ فقط يُرسل طلب مجاني لقائمة النماذج (`GET /v1/models`)، ثم طلب التحليل:
- Claude: النموذج الافتراضي المتحقق منه `claude-sonnet-5-5` إن كان متاحًا في الحساب، وإلا نموذج من قائمة التفضيل في الإعدادات، وإلا أحدث Sonnet متاح.
- OpenAI: أقوى نموذج GPT عام في حساب المستخدم، مثل `gpt-5.1` ثم `gpt-5` ثم `gpt-5-chat-latest` ثم `gpt-5-mini`. تُستبعد نماذج الصوت والصور والتضمين والبحث وCodex وفئة `-pro` المرتفعة التكلفة.
- يُحفظ النموذج المختار في ذاكرة الصفحة حتى مسح المفتاح أو إعادة التحميل.

**أسماء النماذج** في `public/config/models.json`، وتُحدَّث دون إعادة البناء:
- Anthropic: `claude-sonnet-5-5` (افتراضي) و`claude-haiku-5-5` و`claude-opus-5-5`، وقد تُحقق منها من صفحة النماذج الرسمية بتاريخ 2026-10-31.
- خيار المخرجات المنظمة (`output_config.format`) مفعّل فقط لـ`claude-haiku-5-5`، لأنه النموذج الوحيد الذي تأكد ظهوره في قائمة الدعم. بقية النماذج تُطلب منها JSON عبر التعليمات، ثم يُتحقق من البنية في المتصفح.
- عناوين API ثابتة في الكود (`src/providers.ts`)، ولا يمكن تغييرها من ملف الإعدادات أو من الواجهة.

### ما يحتاج مفتاحًا أو مراجعة بشرية قبل الإطلاق

1. تجربة تحليل حقيقي بمفتاح Claude صالح لحالات الاختبار في القسم 9. هدفها مراقبة جودة التفسير، والتزام النموذج بصيغة JSON مع Sonnet وOpus، ومقاومة محاولات توجيه النموذج لتجاهل تعليماته.
2. تجربة تحليل كامل عبر OpenAI من متصفح عادي: صيغة طلب Responses API، والتزام النموذج المختار تلقائيًا بالمخرجات المنظمة، ورابط صفحة المفاتيح.
3. مقارنة كل وثيقة بنسختها الرسمية الحالية على منصة هيئة الخبراء وموقع الهيئة العامة لتنظيم الإعلام، ثم تحديث `currency` و`official_url`.
4. مراجعة بشرية لنسخ الملفين الممسوحين ضوئيًا (`sources/text/*.txt`)، ومراجعة عيّنات من النصوص المفكوكة آليًا مقابل صور الصفحات.
5. مراجعة قانونية لصياغة تعليمات النظام وعرض النتائج.

## 8. المفتاح والخصوصية

- المفتاح في متغير داخل ذاكرة الوحدة `src/providers.ts` فقط. لا يُحفظ في `localStorage` أو `sessionStorage` أو IndexedDB أو الكوكيز، ويُمسح عند إعادة التحميل أو عند الضغط على «مسح المفتاح» أو عند `pagehide`.
- يُرسل المفتاح في ترويسة المصادقة إلى نطاق المزود الرسمي فقط. لا يوضع في عنوان URL ولا في نص المحادثة، ولا يُطبع في السجلات.
- رسائل الخطأ لا تعرض نص خطأ المزود، لأن بعض المزودين يُضمّنون جزءًا مقنّعًا من المفتاح فيه. تُعرض رسالة عربية مع رمز الاستجابة ونوع الخطأ فقط.
- قبل الإرسال الأول يلزم تأكيد التنبيه: «سيُرسل النص والمراجع المختارة إلى المزود الذي اخترته…».
- مخرجات النموذج تُعرض نصًا عبر `textContent` فقط، ولا يُنفذ أي HTML.
- CSP: `default-src 'none'`، والسكربتات من `'self'` فقط، والاتصال محصور في `api.anthropic.com` و`api.openai.com`.
- لا مكتبات خارجية في وقت التشغيل، ولا خطوط من الإنترنت، ولا أدوات تتبع.
- لا يوضع محتوى المستخدم في أي رابط.

## 9. الاختبارات

```bash
npm test
```

```bash
npm run build && node tests/e2e.cjs
```

```bash
node tests/cors-check.cjs
```

- `npm test`: 24 اختبار وحدات (Vitest). تغطي سلامة المراجع، والتطبيع، والاسترجاع، والتحقق من المقتطفات، ورفض الاستشهادات المختلقة، وتحليل المخرجات.
- `tests/e2e.cjs`: 52 فحصًا على نسخة البناء في Chromium.
- `tests/cors-check.cjs`: اختبار CORS حقيقي بمفتاح غير صالح؛ يحتاج اتصالًا بالإنترنت.

**نتائج آخر تشغيل:** 24/24 اختبار وحدات ناجح، و52/52 فحصًا شاملًا ناجحًا.

ما اختُبر فعليًا (الاستجابات في الاختبارات الشاملة **بيانات اختبار** تُحقن داخل المتصفح، وليست نتائج تحليل):

| الحالة | كيف اختُبرت |
|---|---|
| عدم وجود طلبات مدفوعة قبل إجراء صريح | مراقبة الشبكة أثناء الكتابة ولصق المفتاح: صفر طلبات |
| مسح المفتاح وعدم بقائه بعد إعادة التحميل | الحقل فارغ بعد المسح وبعد إعادة التحميل، والتخزين المحلي والكوكيز وIndexedDB فارغة |
| اختيار النموذج تلقائيًا | لا يوجد حقل لاختيار النموذج في الصفحة؛ يُرسل طلب التحليل بالنموذج المختار؛ قواعد الاختيار لها اختبارات وحدات |
| استشهاد مختلق | معرّف غير موجود، أو معرّف حقيقي لم يُرسل، أو مقتطف غير موجود في النص: كلها تُرفض؛ و«مؤشرات تعارض» بلا سند صالح تُعرض «يتطلب معلومات إضافية» مع تحذير |
| مدخل أو مخرج يحتوي HTML أو JavaScript | يُعرض نصًا حرفيًا؛ لا عناصر مُحقنة؛ لا نوافذ تنبيه |
| أخطاء المفتاح والصلاحيات والفوترة والحدود والنموذج والطول والشبكة والاستجابة غير المقروءة | رسالة عربية لكل حالة؛ المفتاح لا يظهر حتى لو ورد في نص خطأ المزود |
| سؤال خارج نطاق الملفات (ضريبة القيمة المضافة) | «لا تكفي المراجع المتاحة للتقييم» محليًا دون طلب |
| الإرسال المتكرر | نقرتان تُنتجان طلبًا واحدًا |
| الإلغاء | يوقف الطلب، مع تنبيه بأن التكلفة قد تُحتسب |
| الواجهة على الجوال (375px) | لا تمرير أفقي، وأهداف اللمس 38px أو أكثر؛ لقطات الشاشة في `docs/screenshots/` |
| لوحة المفاتيح | مجموعات الاختيار تعمل بالأسهم، وحالة التركيز ظاهرة |
| نص له إشكال تسنده مادة واضحة (سجائر إلكترونية) | الاسترجاع يجلب م4/14 من اللائحة وم5/15 من النظام (اختبار وحدات)، والعرض والتحقق اختُبرا ببيانات اختبار |

**ما لم يُختبر بنموذج حقيقي (يحتاج مفتاحًا):**
- نص لا يظهر فيه تعارض.
- حالة تعتمد على استثناء أو معلومة ناقصة.
- نص يحاول توجيه النموذج لتجاهل تعليماته.

ما تحقق منه برمجيًا لهذه الحالات: المسار يعمل، ونص المستخدم يُرسل داخل بيانات JSON موسومة بأنها بيانات لا تعليمات، والتعليمات الثابتة موجودة في رسالة النظام. أما **سلوك النموذج نفسه فلم يُختبر.**
