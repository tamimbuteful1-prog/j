الجزء أ: التجزئة

1) المشاكل الفرعية

قسمت مشكلة الفاتورة إلى خمس مشاكل فرعية. كل وحدة لها شغلة وحدة بس:

#اسم الوحدةالمدخلاتالمخرجات
1قراءة المدخلاتاللي يكتبه المستخدم: اسم الطالب، عدد السندويتشات وسعرها، عدد العصائر وسعرها، نسبة الخصممتغيرات جاهزة بالنوع الصح (أعداد int وأسعار float)
2حساب المجموععدد وسعر السندويتشات، عدد وسعر العصائرالمجموع قبل الخصم
3حساب الخصمالمجموع قبل الخصم، نسبة الخصمقيمة الخصم، والمجموع بعد الخصم
4حساب الضريبة والنهائيالمجموع بعد الخصم، نسبة الضريبة 15%قيمة الضريبة، والمبلغ النهائي
5طباعة الفاتورةاسم الطالب وكل المبالغ اللي فوقفاتورة مرتبة، كل مبلغ برقمين بعد الفاصلة ومعه «ريال / SAR»

2) مين يعتمد على مين

السهم معناه «يعتمد على»: مثلا الضريبة (4) ما تنحسب إلا بعد ما يطلع المجموع بعد الخصم (3).

3) هل تجزئتي صحيحة؟

  • غطت كل المشكلة؟ نعم. كل شي مطلوب بالفاتورة (المجموع، الخصم، بعد الخصم، الضريبة، النهائي، الطباعة) له وحدة تطلعه، والمدخلات كلها لها وحدة تقراها.
  • فيه جزئين يسوون نفس الشي؟ لا. كل وحدة لها شغلة مختلفة: وحدة تقرا، ووحدة تجمع، ووحدة تخصم، ووحدة تضيف الضريبة، ووحدة تطبع. ما فيه حساب يتكرر في وحدتين.
  • كل جزء أقدر أختبره لحاله؟ نعم. مثلا أقدر أعطي وحدة الخصم مجموع 15 وخصم 20% وأتأكد إنها تطلع 3.00 و 12.00 بدون ما أحتاج باقي البرنامج. ووحدة الضريبة أعطيها 12.00 وأتأكد إنها تطلع 1.80.

4) حركات التفكير الحاسوبي الأربع من المشكلة

الحركةمثال من مشكلة الفاتورة
التجزئةقسمت الفاتورة الكبيرة إلى 5 مشاكل صغيرة (مدخلات، مجموع، خصم، ضريبة، طباعة).
التعرف على الأنماطحساب السندويتشات وحساب العصائر نفس النمط بالضبط: العدد × السعر. وكمان الخصم والضريبة نفس النمط: المبلغ × (النسبة ÷ 100).
التجريدتجاهلت التفاصيل اللي ما تأثر على الحساب، مثل نوع السندويتش أو نكهة العصير أو وقت الطلب. اللي يهمني بس: العدد والسعر.
تصميم الخوارزميةكتبت خطوات مرتبة: اقرا المدخلات ← احسب المجموع ← احسب الخصم ← احسب الضريبة ← اطبع (موجودة بالجزء ب).

الجزء ب: الخوارزمية والشيفرة الزائفة

1 و 2) الخوارزمية

START
  // Sub-problem 1: read inputs
  INPUT student_name
  INPUT sandwich_count          // whole number
  INPUT sandwich_price          // SAR
  INPUT juice_count             // whole number
  INPUT juice_price             // SAR
  INPUT discount_percent        // e.g. 20 means 20%
  SET vat_percent = 15

  // Sub-problem 2: subtotal
  SET sandwiches_cost = sandwich_count * sandwich_price
  SET juices_cost     = juice_count * juice_price
  SET subtotal        = sandwiches_cost + juices_cost

  // Sub-problem 3: discount  (decision from Part C)
  IF discount_percent > 50 THEN
      OUTPUT "Warning: discount is more than 50%"
  END IF
  SET discount_amount = subtotal * (discount_percent / 100)
  SET after_discount  = subtotal - discount_amount

  // Sub-problem 4: VAT and final total
  SET vat_amount  = after_discount * (vat_percent / 100)
  SET final_total = after_discount + vat_amount

  // Sub-problem 5: print (every amount with 2 decimals + "SAR")
  OUTPUT student_name
  OUTPUT subtotal, discount_amount, after_discount, vat_amount, final_total
END

ليش هي دقيقة وما فيها غموض؟ كل خطوة فيها عملية وحدة واضحة، وكل متغير له اسم يوضح وش فيه، والترتيب ثابت (ما فيه خطوة تستخدم قيمة قبل ما تنحسب)، وعدد الخطوات محدود وتخلص عند END. فلو أي شخص نفذها حرفيا بيطلع له نفس الناتج.

2) البحث عن الرقم 32 في قائمة مرتبة من 1 إلى 32

طريقة «افحص الكل»: أبدأ من أول رقم وأفحص واحد واحد: 1، 2، 3، ... إلى 32. الرقم 32 آخر واحد، فأحتاج 32 خطوة (هذي أسوأ حالة).

طريقة «احذف النص»: كل مرة أشوف الرقم اللي بالنص، ولأن 32 أكبر منه أحذف النص الأصغر:

ليش «احذف النص» تحتاج قائمة مرتبة؟ لأني لما أشوف الرقم اللي بالنص وأقول «32 أكبر منه، فأكيد هو بالنص الثاني» هذا الكلام صحيح بس إذا الأرقام مرتبة. لو القائمة ملخبطة، ممكن يكون 32 بالنص اللي حذفته، فبحذفه بالغلط وما ألقاه.

شرح الحالة الثالثة

اسم الخطأ: ValueError، وهو خطأ وقت التشغيل (Runtime).

ليش طلع مع إن input() شغال؟ لأن input() فعلا اشتغل صح: هو دايم يرجع اللي كتبه المستخدم كنص (str)، وأخذ النص "three" بدون مشكلة (وهذا واضح من سطر Type before conversion: <class 'str'>). المشكلة صارت بالسطر اللي بعده: int() يحاول يحول النص لعدد صحيح، وهو يعرف يحول نص مثل "3" بس ما يفهم الكلمة الإنجليزية "three"، فيطلع ValueError ويوقف البرنامج.

البرنامج 3: المفروض يطبع 54.00 SAR

price = 20
quantity = 3
discount = 10
total = price * quantity - discount / 100
print(f"Total after discount: {total:.2f} SAR")

توقعي: بيشتغل بدون أي رسالة خطأ، بس الرقم بيطلع غلط، لأن بايثون يسوي القسمة والضرب قبل الطرح، فيطرح 0.1 ريال بس بدل 10%.

لما شغلته:

Total after discount: 59.90 SAR

الحساب اللي صار: 60 − (10 / 100) = 60 − 0.1 = 59.90، والصحيح: 60 − (60 × 10%) = 54.00.

التصليح: أحسب الخصم من المجموع، وأحط أقواس:

price = 20
quantity = 3
discount = 10
total = (price * quantity) * (1 - discount / 100)
print(f"Total after discount: {total:.2f} SAR")
Total after discount: 54.00 SAR

السؤال الأخير

قرار تصميم خذيته وليش: حطيت لكل خطوة حساب متغير وسيط خاص فيها (subtotal، discount_amount، after_discount، vat_amount، final_total) بدل ما أكتب كل الحساب بسطر واحد طويل. ليش؟ لأن كل متغير يطابق مشكلة فرعية من الجزء أ، فلو طلع رقم غلط بالفاتورة أعرف بسرعة أي خطوة فيها المشكلة، وكمان الفاتورة تحتاج تطبع كل هالقيم أصلا. وحطيت نسبة الضريبة بمتغير ثابت VAT_RATE = 15 عشان لو تغيرت الضريبة أعدلها بمكان واحد.

تحسين أبغى أضيفه لو عندي وقت أكثر: أخلي البرنامج متين أكثر: لو المستخدم كتب كلمة مثل three أو رقم سالب، ما يوقف البرنامج، بل يطلع له رسالة واضحة ويطلب منه يكتب الرقم مرة ثانية. وأبرمج كمان التنبيه اللي محجوز بالتعليق TODO لما يكون الخصم أكبر من 50%.
